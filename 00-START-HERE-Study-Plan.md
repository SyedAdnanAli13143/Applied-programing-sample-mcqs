## The Most Important Rule For Tomorrow
**There is NO negative marking.** This changes your entire strategy:
- **Never leave a question blank.** A guess has a chance of being right; a blank is guaranteed zero.
- If you don't know an answer, eliminate the options you *know* are wrong, then guess among what's left.
- Don't get stuck on one hard question — mark it, move on, come back if time allows. With 50 Qs in 60 min, you have ~72 seconds per question on average.

## What Kind Of Questions To Expect
This is an *exemption* test, meaning it checks whether you already know intro-level Programming Fundamentals, OOP, Data Structures, and Algorithms (the topics people who skip the actual course would need). Expect:
1. **"What does this code output?"** — small C++/Java snippets, you trace through them mentally.
2. **"What is the time complexity of X?"** — Big-O identification.
3. **Definition / concept MCQs** — "Which of these is NOT a pillar of OOP?", "Which data structure is FIFO?"
4. **"Which data structure/algorithm fits this situation?"** — applied reasoning.
5. **True/False style statements** about inheritance, pointers, sorting, etc.
